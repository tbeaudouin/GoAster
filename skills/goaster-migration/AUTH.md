# Authentication and authorization

Use this skill only in a paired private Telegram conversation. Check the protected environment as in step 1; never request a pasted provider token in chat. Obtain one private spending approval for the exact `server_name`, `server_type`, `locations` (including an omission or empty list), and `immediate` or `eventual` timing. Follow step 4 for creation, retries, and any fresh approval.

Before creation, verify private delivery is available. Send the setup URL and SSH private key only to the revalidated paired owner in separate private messages; the key is a directly uploadable `id_ed25519` attachment containing only key bytes. Keep the token, URL, key, and request body out of model input/output, tool output, cron messages, and logs. Do not persist them or make extra copies; the intended protected environment storage is allowed for the token. If delivery fails after creation, report the state; do not automatically resend, replay, or create another server.
