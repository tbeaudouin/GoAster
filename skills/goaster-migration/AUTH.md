# Authentication and authorization

Use this skill only in a paired private Telegram conversation. Obtain explicit conversational approval for one immediate or eventual creation with one exact fixed target name, the exact server type and optional strict locations. The agent may generate or propose the name in this workflow; no separate naming workflow, approval record or approval code is required. This skill grants no access to Hetzner, GoAsterWeb, Telegram, SSH, or secrets; follow `goaster-env` and `hetzner-auth` for the configured credential source.

The provider token is request-scoped. The private key and setup URL go directly to the revalidated paired Telegram owner, never to the model, ordinary chat, logs, or local persistence. Stop before creation if private delivery is unavailable. The setup URL is a separate message and the SSH private key is a separate key-only attachment. If delivery fails after creation, report the created state and do not resend or create again automatically.

A lost response can mean a server was created. Every approved immediate or eventual request supplies the same exact `server_name` matching `goaster-migration-[0-9a-f]{16}`; an ordinary generic cron message reuses it every 1800 seconds for an eventual request. The Web endpoint performs existing public admission and rate bookkeeping first, then the read-only exact-name lookup before capacity, key, or billable create work. Retry only explicit `not_created` plus `no_capacity`. `target_exists` stops normally with no new server created and no implication that setup or SSH key material was recovered. Success, handoff failure or partial delivery, lookup failure, timeout or unknown, and any other failure are terminal; no overlap, replay, or automatic recreation is allowed. A qualifying scheduled turn may make one create call and cannot add jobs. The model must follow the message; request terms are not independently bound. Before any new interactive attempt, warn about duplicate charges, suggest optional account inspection, and obtain fresh conversational approval. This runtime does not read, migrate, or resume files from older installations.
