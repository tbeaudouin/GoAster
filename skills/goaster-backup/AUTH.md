# Authentication

Use `goaster-env` and `hetzner-auth` for secret lookup and read-only target verification. The coordinator's single approval covers snapshot creation, cost and retention, including an unavailable estimate; standalone backup requires approval. Price lookup is agent best effort; never ask the user to research or quote the console snapshot price or supply its amount, currency, or billing period. Do not invent a price. Do not delay for a price or retention-only approval after a quote becomes known. Use established retention or state the default of keeping the snapshot until the user requests deletion alongside cost or uncertainty in the one approval; do not delete snapshots automatically. Respect explicit user limits.

At the backup step, after the one applicable approval, create and verify the snapshot immediately, without first asking about essential off-server data, external databases, object storage, a separate recovery plan, or independent console access. External-data recovery planning is outside this routine snapshot workflow and is not a blocker. A snapshot scope limitation may be a concise FYI, not a question; do not assert that the snapshot covers off-server data. Verify an uncertain provider mutation before proceeding; do not repeat it. Do not ask for project names or IDs. Never include credential values in reports, logs, commands, or handoffs.
