# One-shot migration machine creation

On the migration-enabled public web service, send `POST /api/migration/create` over HTTPS. Each request is one create attempt and must include `server_name` as an exact target name matching `^goaster-migration-[0-9a-f]{16}$`; the service first performs existing public admission and rate bookkeeping, then uses the same bearer token and project for a read-only exact-name lookup before capacity, SSH-key, or billable server-create work. The caller still must reconcile uncertain outcomes with Hetzner manually; never automatically repeat an uncertain create.

Generate a fresh 32-byte cryptographically random secret for each request, encode it as unpadded base64url, and send `Authorization: Bearer <secret>`. This is the owner handoff credential, not an independent service access credential: possession of a valid Hetzner token authorizes provisioning. Generate a fresh Ed25519 login key pair and keep its private key for the browser setup. Send `Content-Type: application/json`:

```json
{"hcloud_token":"<HCLOUD_TOKEN>","server_type":"cx22","server_name":"goaster-migration-0123456789abcdef","locations":["fsn1"],"login_public_key":"ssh-ed25519 <canonical-public-key>"}
```

`server_name` is required for the immediate and eventual one-shot create flows. The caller supplies the same approved exact name on every attempt. After existing public admission and rate bookkeeping, the service performs a read-only lookup of that exact name in the same provider project before capacity, key, or billable create work. If it exists, return HTTP 409 with `creation_state: "not_created"` and `error: {"code":"target_exists","stage":"provider","http_status":409}`, plus `server_id` and `server_label`; do not return setup material or adopt the existing server. If the lookup fails, return `creation_state: "not_created"` with a provider lookup-failure code and never create. If the lookup confirms absence, create the requested exact name and preserve the successful handoff contract.

`locations` is optional; an empty array or omission permits any compatible available location. A nonempty list is strict; entries must be unique valid location names. The exact requested server type is required. The service determines its x86 or ARM architecture from Hetzner and validates the matching Ubuntu 24.04 system image, type and location before provisioning. Public IPv4 is enabled; IPv6 and private networks are not requested. Pricing is informational and no price cap is accepted. No fields beyond those shown are accepted.

A successful response has HTTP 201 and `creation_state: "created"`, `attempt`, `server_label`, `server_id`, `ip`, `location`, `expires` (Unix seconds), and `setup_url`. The URL contains the owner secret in its fragment; treat the entire URL as a credential and open it privately. Upload the matching private key in the browser. The existing provider identity verification, callback host key, pinned SSH, and shared authorization flow remain in force. The operation identity is generated by the service solely for the expiring handoff.

Errors have `creation_state` and `error: {"code", "stage", "http_status", "provider_code", "provider_message", "provider_fields"}`; `provider_code` and `provider_message` are present only when safely available, and `provider_fields` is a bounded array of `{ "field": string, "messages": string[] }`. Provider messages, field names, and field messages come from fixed allowlists; never copy raw provider bodies, URLs, credentials, or other private text. GoAster uses an explicit valid `creation_state` as the outcome: a missing or unrecognized state is `unknown`, regardless of HTTP status or error metadata. In particular, HTTP 422 or `invalid_input` metadata alone never establishes `not_created` in GoAster. An explicit `not_created` is used only when the service supplies that state based on authoritative evidence that no server was created; it does not by itself prove that no create request was dispatched. Timeout metadata makes an explicit `not_created` outcome `unknown`; explicit `created` and `unknown` states are preserved when error metadata conflicts, and a confirmed `created` result is not downgraded by a timeout. If an explicit `created` response fails error-envelope or exact-name lookup validation, GoAster returns `created` with `code: "response_unusable"`, retains only sanitized server identity, and delivers no handoff. Other missing, unusable, or contradictory responses remain `unknown`; inspect the Hetzner project before any new request. `no_capacity` identifies a valid type and image with no available permitted location (HTTP 409). An SSH key may already have been registered with Hetzner even when the server is `not_created`. `created` on an error means Hetzner confirmed a server but setup handoff could not be completed; the response includes any known `server_id`, `ip`, `attempt`, `server_label`, `location`, and `expires` for manual reconciliation. The caller must also treat a lost HTTP response as unknown. Do not log tokens, bearer secrets, request bodies, private keys or setup URLs.

Validation is offline: `go test ./...` and `go vet ./...`. Provider calls in tests use fakes or local HTTP test servers; no cloud credentials or production services are required.
