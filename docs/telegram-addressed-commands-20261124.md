# Telegram addressed commands

The adapter obtains its bot username from Telegram's authenticated `getMe` response at startup and refuses to start if the bot identity is missing or invalid. Before polling dispatch and handler checks, it strips a matching, case-insensitive username suffix from a recognized first command token, preserving arguments and leading whitespace. Valid command tokens addressed to another bot are ignored, including unknown command names. Existing authorization, chat, topic, attachment, and command checks still apply. Captions use the same handling when they are the message text.

Offline regression tests cover catalog commands, captions, authorization, group and supergroup guards, identity failures and redaction, and polling dispatch and ordering for addressed stop, clear, restart, and other-bot commands. Validation used `/usr/local/go/bin/go` version 1.25.9 with the requested PATH and `GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off`: focused Telegram and diagnostics tests, `go test ./...`, `go vet ./...`, and `go build ./...` passed. Independent parent validation also passed the full unfiltered tests, vet, build, and `go test -race ./internal/telegram ./internal/telegramcommands ./internal/diagnostics` with the same offline settings. No live Telegram or network integration was performed.
