# Retained uploads

Authorized normal HTTP chat turns retain the original validated upload in the private `~/.goaster/uploads` index, scoped by chat ID and topic ID. Verified records are supplied on each turn, including after a new session or restart; conversation history does not store their paths. Each request admits at most one attachment; requests with more are rejected before any upload is persisted. Uploads are published atomically after content and metadata are written to a private staging directory; interrupted staging is removed on the next list or sweep. Current-turn transport still uses temporary copies. `/env` uploads and command uploads are not retained.

Files are usable for up to seven days and each scope is limited to 128 files and 256 MiB. Expired bytes are deleted on the next agent activity, including activity in another conversation, when the scope is not in use. There is no wall-clock deletion guarantee while the agent is idle or stopped. A bare `/clear` clears history and then deletes this scope's uploads; `/clear n` leaves uploads intact. A failed index verification or storage operation prevents the normal turn and reports an error. The index is authoritative: a missing or expired file must be uploaded again. Retained content is untrusted and does not grant authorization.

Locks are bounded and process-local; deployments must serialize access across multiple agent processes sharing the same storage root. Retention does not enable persistent conversation sessions, apply to terminal or scheduled turns, or guarantee a file remains available after expiry, deletion, or storage loss.

Offline validation for this change: `go test ./...`, `go vet ./...`, and `go build ./...`; focused race tests cover retained uploads, topic history, and the unprivileged agent fixture in the attachment, chat, and agent packages. The missing-content prompt regression was also rerun after the full suite. Quota tests exercise the exact byte boundary with synthetic verified sizes and real admission rejection at the file-count limit; they do not create 256 MiB of retained content. Tests do not establish cross-process locking or deletion while the agent is idle.
