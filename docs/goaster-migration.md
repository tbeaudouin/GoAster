# Migration

See [API-first migration integration](api-first-migration-20261116.md) and the bundled `goaster-migration` skill. The normal immediate `goaster_migration` create remains available. After conversational approval for one exact type and optional strict locations, the existing generic `cron` tool can carry one protected one-shot eventual-create instruction at 1800 seconds; there is no migration-specific schedule action. Scheduling generates and persists one exact `goaster-migration-[0-9a-f]{16}` target name, and every attempt sends that same `server_name`; the Web endpoint performs existing public admission and rate bookkeeping first, then the read-only exact-name lookup before capacity, migration-record state, key, or billable create work. It retries only an explicit `not_created` plus `no_capacity`; `target_exists` is a normal stop with no new server or setup/key recovery claim. Success, handoff failure, lookup failure, timeout or unknown, and every other failure are terminal. Dedicated migration monitors are retired, and old protected records are untouched and do not resume or replay. The setup URL and key-only SSH attachment are delivered separately to the revalidated paired private owner; there is no secret local persistence.
