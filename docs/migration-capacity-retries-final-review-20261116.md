## P2 — Provider transport categories do not establish temporary failure

**Location:** `internal/migration/runtime.go:590–591` (`availabilityHTTPErrorMayRetry`); corresponding policy in `skills/goaster-migration/SKILL.md:258–259`.

The source automatically retries `provider_dns_failure`, `provider_tls_failure`, and `provider_transport_failure` whenever the envelope has HTTP 500/502/503/504, `stage=provider`, and an empty `provider_code`. Those fields establish the error's origin and category, but provide no evidence that it is temporary. The supplied paired Web review explicitly says these categories alone do not prove temporary failure. The local decoder (`internal/migration/migration.go:871`) preserves no additional transient discriminator.

For example, an HTTP 502 response containing `{"version":"v1","error":{"code":"provider_tls_failure","stage":"provider","http_status":502}}` passes this gate even when the underlying failure is an expired/untrusted certificate or hostname mismatch. Permanent DNS failures such as an invalid hostname/NXDOMAIN and unclassified provider transport/configuration failures follow the same path. The first two failures return successful `monitoring` results and rearm the monitor; manual review occurs only on the third check, about an hour later, with the generic budget-exhausted diagnosis. This violates the required immediate stop for configuration and unknown failures. A valid envelope and gateway status do not resolve that ambiguity. The regression at `internal/migration/capacity_retry_regression_test.go:144–147` currently requires the overly broad DNS classification to succeed.

**Required correction:** Treat these three provider categories as terminal under the current contract. If retries are needed, first establish an explicit, safely allowlisted contract discriminator backed by Web's actual temporary-cause classification, then gate source retries on that evidence. Keep proven timeouts and established transient provider causes separate. Update the skill/validation policy and add offline regressions showing that certificate validation, permanent DNS, and unknown transport envelopes stop on the first check with zero retries and zero create calls; retain positive coverage for proven temporary failures.
