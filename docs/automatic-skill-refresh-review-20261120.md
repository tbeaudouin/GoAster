# Automatic skill refresh review - 2026-11-20

Verdict: the normal refresh and mid-batch continuation paths are suitable for offline validation, with the interrupted-turn durability limitation below. Changed selected instructions are loaded automatically without an accept or clear step. Missing, invalid, oversized or unsaveable guidance still stops the workflow. The refresh does not itself grant authorization; current skill requirements and the scope of user approval remain relevant.

The review found that a model-requested `load_skill` output could retain old AUTH guidance alongside the refreshed snapshot. Refresh now replaces that output with a reference to the current guidance while preserving its call/output pair and completed action results in the continuation. Regression tests cover both replacement and an actual refresh after a load. The churn-limit response was also corrected: it tells the user to check potentially completed actions rather than claiming their results were retained.

The existing conversation and summary are preserved when the digest is checkpointed, including across compaction and restart. Mid-batch refresh carries completed call/output pairs forward and drops the unexecuted remainder; discarded call IDs are not executed if repeated. Refresh churn is bounded, and its latest digest and warning are retained without leaving a failed-checkpoint flag. These checks do not establish exactly-once execution across crashes or across later turns: individual tool outputs from a turn cut short by the churn limit are not durably stored in conversation history. The warning survives a successful turn save, but users must check action results before repeating them. This is a remaining limitation for the requested durable completed-action evidence, not a guarantee of durable nonreplay. Compaction and ordinary session persistence have their existing bounded-history behavior.

The changes do not add pointers, disclose skill contents in refresh diagnostics, or introduce an approval from the skill itself. Tool-call pairs remain matched in the tested refresh path. The review is limited to the uncommitted source and offline tests; concurrent file changes can still occur between a check and an action, and live provider behavior was not tested.

Checks: offline `go test ./...`, `go vet ./...`, focused race tests for skills and the provider, focused refresh/churn regressions, and `git diff --check` passed using `/usr/local/go/bin/go` with network module fetching disabled. The full suite and vet ran before the final warning and additional focused assertions; the focused tests cover those changes. No external service, runtime, secret, source reset, GitHub operation, commit, or push was used.
